# Project Requirement Plans

Store approved feature and change plans here, organized by project and feature.

```text
projects/
  <project-name>/
    <feature-name>/
      requirements.md
      (optional design notes, diagrams, and decision records)
```

Use lowercase kebab-case names. Start from [the Feature Requirements Template](../docs/templates/FEATURE-REQUIREMENTS-TEMPLATE.md).

The approved `requirements.md` is the durable requirements baseline. Kanban cards and pull requests should link to it. Update the document when the Team Lead approves a material change; do not rely on chat history or card comments as the only record of requirements.

See [AI Development Workflow and Branching](../docs/AI-DEVELOPMENT-WORKFLOW-AND-BRANCHING.md) for the planning, handoff, review, deployment, and branch workflow.
